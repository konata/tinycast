# Tinycast personal fork: requirements and implementation

This fork record covers the work added after the fork point `db35515` (the merge base with the locally recorded `upstream/main`). It describes the fork through `d7e8c16` on `main`, as inspected on 2026-10-13. The tracked `AGENTS.md` and `docs/` remain the general project guidance; this file records the user's fork-specific requests, current implementation, and evidence boundaries.

## Implemented requirements

1. **Launch an exact user alias with Space.**
   - **Request:** When the launcher query exactly matches a user-defined alias, pressing an unmodified Space should activate that row like Return. A partial alias, an app's ordinary name, or text that merely contains the alias must keep normal typing behavior.
   - **Implementation:** `RootPaletteView` handles Space on the focused search `TextField` itself because that field consumes printable keys before an ancestor handler sees them. It ignores modified presses, marked-text composition, open menus and control lists, focused extension arguments, and an unfocused search field. `LauncherScreen.spaceActivation(matching:)` trims the query, rejects empty queries and embedded spaces, scans its visible entry and fallback rows, and compares `FuzzyMatch.normalized` values against `AppIndex.userAlias(for:)`. The `PaletteScreen` protocol declares the hook so calls through the screen existential dispatch to `LauncherScreen`; other screens use its `nil` default.
   - **Code:** `Tinycast/Palette/RootPaletteView.swift`, `Tinycast/Palette/PaletteScreen.swift`, `Tinycast/Features/Launcher/UI/LauncherScreen.swift`, `Tinycast/Features/Launcher/Service/AppIndex.swift`. Added and corrected in `5248bc9`, `df7951f`, and `1342d1e`; temporary diagnostics were removed before the merge at `dd1f966`.

2. **Keep ordinary window switching and cross-Space summoning as distinct commands.**
   - **Request:** Preserve the existing Search Open Windows / **Switch Windows** action, which activates a window in its own Space, and add **Summon Window**, which brings a selected window to the Space of the Tinycast palette. The new command needs its own shortcut in Settings › Navigation.
   - **Implementation:** `CommandID.summonWindow` is a plain launcher command with its own palette mode, screen, session, and coordinator. `SettingsTab.navigation.ownedCommands` places it in Navigation; `navigationEnabled` gates both its command and shortcut and is off by default. The two commands share the row model, icon rendering, fuzzy query, and base ordering without sharing their discovery or activation semantics.
   - **Existing Switch Windows path:** `WindowSwitchSweep.snapshot` visits regular, running applications from `NSWorkspace.shared.runningApplications`, reads each app's `kAXWindowsAttribute` through `AXUIElementCreateApplication`, and retains `AXStandardWindow` elements. It allows minimized windows and does not require a frame. Return unminimizes, raises, and activates the chosen window, which may switch macOS to that window's existing Space. There is no explicit Space or display filter in this path, but an inactive-Space window can be absent from the app's AX window list; Clash Verge was observed in that state.
   - **Code:** `Tinycast/Features/Launcher/Model/CommandID.swift`, `Tinycast/Features/Settings/Panes/NavigationSettingsView.swift`, `Tinycast/Features/WindowSwitcher/Service/WindowSwitchSweep.swift`, `Tinycast/Features/WindowSwitcher/UI/WindowSummonCoordinator.swift`, `Tinycast/Features/WindowSwitcher/UI/WindowSummonScreen.swift`, and `docs/features/navigation.md`. Summon began in `fdb3c0c`.

3. **Discover summon candidates across every Space on every display.**
   - **Request:** The picker must list eligible windows from inactive Spaces and the second display as well as the current Space. An AX-only application sweep was insufficient: moving Clash Verge to an inactive Space made it disappear from Switch Windows while it remained discoverable by Summon Window.
   - **Implementation:** `WindowSummonInventory.snapshot` gets off-screen window IDs and titles from `SCShareableContent.excludingDesktopWindows(true, onScreenWindowsOnly: false)`. The Objective-C bridge obtains managed displays and Spaces with `SLSCopyManagedDisplaySpaces`, calls `CGSCopyWindowsWithOptionsAndTags(..., 0x7)` for **each** managed Space, unions those IDs with ScreenCaptureKit's IDs, and reads `CGWindowID`, PID, title, geometry, level, parent, attributes, tags, and fullscreen state through `SLSWindowQueryWindows` and its iterator. The per-Space walk also records exact window-to-Space membership; a targeted `SLSCopySpacesForWindows` lookup can fill a missing membership. The bridge converts each managed display UUID to a numeric display ID with `CGDisplayGetDisplayIDFromUUID`. WindowServer work is isolated in `WindowSystemBridge` and the snapshot's blocking record processing runs off the main actor.
   - **Code:** `Tinycast/Features/WindowSwitcher/Service/WindowSummonInventory.swift`, `Tinycast/Platform/WindowSystemBridge.{h,m}`, `Tinycast/Tinycast-Bridging-Header.h`. The complete per-display, per-Space enumeration is the current implementation from `d7e8c16`; earlier code did not establish that coverage.

4. **Offer user-facing windows while retaining valid inactive-Space candidates.**
   - **Request:** Remove obvious helper surfaces and Space-less entries that have no useful summon target, without dropping a real window simply because AX cannot expose it before a move. The Mill and other-app observations showed that AX availability can change when the app or Space becomes active.
   - **Implementation:** The inventory keeps windows owned by running, nonhidden, nonterminated applications other than Tinycast; it does not require the app's activation policy to be `.regular`. It requires a root surface (`parentWindowID == 0`), positive alpha, no hidden tag, normal level or fullscreen, useful geometry or minimized state, and a nonblank title. It drops an ordered-out nonminimized window assigned to any display's currently active Space. A Space lookup that **succeeds and returns no membership** excludes the row. A failed lookup remains selectable; a missing AX match before moving is not a filter, because an inactive-Space window can lack a published AX element until later.
   - **Current limit:** A failed Space lookup can still produce `? @ ?`, and a WindowServer candidate without a pre-move AX element may later move but fail to focus. The picker does not guarantee that every listed row can be independently summoned; native tab and custom-toolkit behavior varies. These are current behaviors, not completed filtering requirements.
   - **Code:** `WindowSummonInventory.swift`, `WindowSystemBridge.m`, and `docs/features/navigation.md`. The confirmed-empty-Space exclusion was added in `eff3909`.

5. **Show location and put the destination Space last.**
   - **Request:** Append each row's `Space ID @ Screen ID` after its app name. Prefer windows from other Spaces and displays; place windows already in the palette display's active Space at the end, including during a text search.
   - **Implementation:** `WindowSummonLocation` formats each reported membership using the raw managed Space ID and `CGDirectDisplayID`; a window in multiple Spaces lists every pair. A missing screen mapping displays `Space ID @ ?`; no known location displays `? @ ?`. `WindowSummonOrder.rank` partitions remote, unknown, and current-destination windows **before** fuzzy ranking and the global 200-row cap. `WindowSummonCoordinator.refreshDestination` re-evaluates the destination and ordering when the palette moves to another display or that display changes Space.
   - **Code and checks:** `Tinycast/Features/WindowSwitcher/Model/WindowSummonLocation.swift`, `Tinycast/Features/WindowSwitcher/Service/WindowSummonSession.swift`, `Tinycast/Features/WindowSwitcher/UI/WindowSwitchList.swift`, `Tinycast/Features/WindowSwitcher/UI/WindowSummonCoordinator.swift`, and pure harness cases in `Tests/window-switch-test.swift`. Added in `2c32431`.

6. **Move the exact selected window into the palette's current desktop Space.**
   - **Request:** Return on a Summon Window row should move that window, including from another display when possible, to the Space currently shown on the palette's display and focus it. It should not merely switch to the source Space or move a different window with the same title.
   - **Implementation:** At activation the coordinator reads the palette panel's current `NSScreen`, resolves its display UUID to the currently managed Space, and rejects a non-desktop destination. It hides the palette without restoring the displaced app's focus and verifies the selected `CGWindowID` still belongs to its PID. For a fullscreen source it first finds that exact AX window ID, exits fullscreen if allowed, and waits for the same window to settle in a desktop Space. The bridge invokes `SLSBridgedMoveWindowsToManagedSpaceOperation` for the exact ID; the coordinator waits for WindowServer to report membership in the destination, with a second attempt if necessary. It then unhides the app if needed, looks for the same ID in AX windows, focused window, and main window using `_AXUIElementGetWindow`, unminimizes, corrects placement to intersect the target display's visible frame, raises and activates, and verifies focus and destination membership. A notification distinguishes a confirmed move with incomplete AX/focus from a complete failure or a window already in the destination.
   - **Limits:** The move operation and AX-to-window-ID mapping are private macOS interfaces resolved at runtime. Fullscreen windows require their exact AX element before leaving fullscreen. A successfully moved window may still withhold AX long enough that Tinycast cannot verify final focus.
   - **Code:** `Tinycast/Features/WindowSwitcher/UI/WindowSummonCoordinator.swift`, `Tinycast/Features/WindowManagement/Service/AXWindowAccess.swift`, `Tinycast/Platform/WindowSystemBridge.m`, and `docs/features/navigation.md`.

7. **Gate Summon Window with the permissions its inventory and action need.**
   - **Request:** Explain missing permissions and avoid acting on another app's windows without the necessary macOS grants.
   - **Implementation:** The command checks Accessibility and Screen Recording when opening and again on Return. ScreenCaptureKit supplies other applications' off-screen titles; the usage text is in `Tinycast/Info.plist`. Missing grants use Tinycast's own guidance and link to System Settings. Switch Windows retains its Accessibility-only path. Re-entering Summon Window starts a fresh snapshot so old window IDs do not survive a previous palette presentation.
   - **Code:** `Tinycast/Features/WindowSwitcher/UI/WindowSummonCoordinator.swift`, `Tinycast/Platform/Permissions.swift`, `Tinycast/Info.plist`.

8. **Build and distribute personal packages without a local Xcode installation.**
   - **Request:** The user prefers GitHub Actions with macOS 26 and Xcode 26 for compilation, wants lint/static review before commits, and chose direct updates to this fork's `main` rather than a PR for the Summon feature cycle. The installed daily app should retain its existing settings.
   - **Implementation:** `.github/workflows/verify.yml` runs on pushes to `main` and `codex/**` and on pull requests; it runs `Scripts/lint.sh`, `Scripts/run-tests.sh`, and an unsigned Debug `xcodebuild`. `.github/workflows/personal.yml` builds stable on each `main` push and supports manually dispatched `stable` or `dev` builds. Its macOS-26 runner selects Xcode 26, imports the self-signed signing identity from repository secrets, and builds stable as arm64 Release `Tinycast.app` with `com.tinycast.app`, preserving the production preferences namespace. Dev uses the separate Debug identity. Packaging verifies the signature, creates a `ditto` zip, uploads a workflow artifact, and overwrites the fixed rolling GitHub release asset under `personal-stable` or `personal-dev`. Successful stable runs target the fork's fixed `personal-stable` release URL.
   - **Evidence and limits:** The workflows encode the build gates and previous runs produced a testable personal package; this record does not claim the current commit was rebuilt after these documentation edits. Signing requires `SIGNING_P12_BASE64` and `SIGNING_P12_PASSWORD` secrets, whose values must never be copied into this document. The personal workflow publishes an artifact and release; it does **not** install the app on the user's Mac automatically.
   - **Code:** `.github/workflows/verify.yml`, `.github/workflows/personal.yml`, `project.yml`, and `Scripts/verify-signature.sh`. Introduced in `711bb84`, `bf877db`, `ed36a51`, `9decb2a`, and `09848f1`.

9. **Provide an optional upstream-update and local-install command.**
   - **Purpose:** Make it possible to pull upstream changes into the personal fork, trigger the personal CI build, obtain its stable package, and replace `/Applications/Tinycast.app` while keeping the same bundle identity and preferences.
   - **Implementation:** `update.sh` fetches and merges `upstream/main`, pushes `origin/main`, watches a GitHub Actions run, downloads `tinycast-personal-stable`, expands `personal-stable.zip`, quits Tinycast, copies the app into `/Applications`, removes quarantine, and opens the app. It is an optional local script, separate from CI.
   - **Current limit:** The script selects the most recent repository run with `gh run list --limit 1`; it does not prove that run belongs to the just-pushed commit or even to the intended workflow. A merge conflict also needs manual resolution. Verify the run and package identity before treating a script execution as an end-to-end update.
   - **Code:** `update.sh`, added in `deab1bd`.

## Verification and open investigation

- `Tests/window-switch-test.swift` exercises pure location formatting, multi-Space labels, remote-first/current-last ordering, typed-query ordering, and the 200-row cap. It does not simulate WindowServer, AX, cross-display movement, signing, or installation. The current project-wide gates remain those in `AGENTS.md` and `docs/testing.md`.
- `docs/features/navigation.md` records disposable macOS 26.6.1 probes across two displays and five Spaces, including a move from the second display to the primary display without changing either active Space. Those probes and the user's installed-build observations are narrower than a guarantee for every app and window toolkit. A temporary cross-display test window was reported difficult to exit; any future disposable harness needs a clear teardown path.
- The inactive-Space Clash comparison established the design boundary: Switch Windows starts with applications' `kAXWindowsAttribute`, while Summon Window starts with WindowServer IDs across Spaces. Reusing the AX-only switch sweep as Summon's sole candidate source would lose the inactive-Space windows the user asked to summon. AltTab's all-Space behavior was examined as research; its additional AX matching and remote-token scan have **not** been implemented in this fork.
- A failed AX read and a confirmed absence are different facts. Do not document temporary AX unavailability as proof that a physical window is a menu popup, closed, or safe to exclude. Investigate candidate quality with exact window IDs, Space membership, and live behavior before tightening the scan.
- For the initial documentation review on 2026-10-13, source review and the `window-switch-test` harness passed. The full local harness finished with 22 of 73 harnesses failing under Command Line Tools / Swift 6.1.2 because this checkout lacks its required Xcode 26 toolchain and SDK; `Scripts/lint.sh` could not load `sourcekitdInProc.framework`. That local review did not include a build, installation, or new runtime test.
